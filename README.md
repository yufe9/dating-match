# 소개팅 매칭 로직 (파이썬 콘솔)

소개팅 **앱**이 아니라 **매칭 로직**입니다. 번호 하나를 넣으면 반대 성별 중 추천 상대와,
그 상대를 고른 과정·이유를 콘솔에 보여 줍니다.

- **API 키 없이 동작합니다.** LLM을 부르지 않고, 임베딩도 내 컴퓨터(CPU)에서 계산합니다.
- **첫 실행 때 임베딩 모델(`intfloat/multilingual-e5-small`, 약 470MB)을 한 번 내려받습니다.** 이후엔 캐시를 씁니다.
- **모든 프로필은 가상 인물입니다.** `men.csv`(M01~M35), `women.csv`(W01~W35) 70명 모두 지어낸 사람입니다.
- **v2 기믹**: 연애 예능처럼 쌍방 확인 → 72시간 여행 → 커플 지원금까지 시즌 하나를 시뮬레이션합니다. ([아래](#v2-기믹-이번-시즌))
- **시각화**: 무작위로 뽑은 한 쌍(M06 × W22)의 분석 페이지 → [docs/index.html](docs/index.html)
  ([바로 보기](https://yufe9.github.io/dating-match/))

## 설치 → 실행

```bash
pip install -r requirements.txt

python match.py          # 번호를 물어봅니다 (M07, W12, all, season, check)
python match.py M01      # M01 한 명: 1~4단계 추천 + 의외의 궁합 + 이번 시즌(짝·여행·커플)
python match.py all      # 70명 전원의 1위만 한 줄씩
python match.py season   # 시즌 전체: 화살표 → 안정 매칭 → 여행 자격 → 여행 → 커플·지원금
python match.py check    # 자체 점검 + 시각화 기준값(M06 × W22) 확인
```

Python 3.10 이상에서 동작합니다(3.13에서 확인).

## 4단계 구조

| 단계 | 하는 일 | 방식 |
|---|---|---|
| 1. 거르기 | 하나라도 걸리면 제외. **나→상대, 상대→나 양방향**으로 검사 | 규칙 |
| 2. 후보 추리기 | 거르기 통과자 중 문장이 비슷한 상위 **K=10명** | 로컬 임베딩 |
| 3. 순위 다시 매기기 | 100점 만점 규칙 점수로 재정렬 | 규칙 점수 |
| 4. 이유 설명 | 1위의 항목별 점수표 + 점수 상위 3개 항목으로 한 문장 | 규칙 |

**1) 거르기 조건**: 본인·같은 성별 / 희망 나이 / 흡연(흡연상대=불가인데 상대가 가끔·흡연) /
종교 일치(필수) / 자녀 계획 일치(필수인데 원함↔원치않음, 모름은 통과) / 같은 시 거주(같은시만) /
희망 키(적은 경우만). 조건별로 걸린 인원을 **조건마다 따로** 셉니다(한 사람이 여러 조건에 걸리면 각각 들어가므로,
조건별 인원의 합은 실제 제외 인원보다 클 수 있습니다). CSV 값은 읽을 때 검사해, 정해진 선택지가 아니면
어느 사람의 어느 칸인지 알려 주고 멈춥니다.
통과자가 0명이면 "조건에 맞는 사람이 없습니다"와 가장 많이 거른 조건을 안내하고 2~4단계를 건너뜁니다.

**2) 임베딩**: `자기소개 + 관심사 + 주말스타일 + 결혼의향 + 자녀계획`을 한 문장으로 잇고,
e5 규칙에 따라 양쪽 모두 앞에 `query: `를 붙입니다(사람↔사람은 대칭이므로).
벡터는 `embeddings.json`에 저장해 재사용하고, 프로필 내용이 바뀐 사람만 다시 계산합니다(내용 해시 비교).
모델을 불러오지 못하면(인터넷 없음 등) 이유를 한 줄 알리고 통과자 전원을 3단계로 넘깁니다.

**3) 규칙 점수 (100점)**

| 항목 | 배점 | 계산 |
|---|---|---|
| 가치관 | 20 | 결혼의향 같으면 10, 한 칸 차이 5 / 자녀계획 같으면 10, 한쪽이 모름이면 5 |
| 생활습관 | 20 | 음주·운동·주말스타일·반려동물 각 5점: 같으면 5, 한 칸 차이 2 (반려동물 키움↔싫음 0) |
| 관심사 | 20 | 겹치는 관심사 1개당 5점, 최대 20 |
| 성격·소통 | 10 | 연락빈도 같으면 6, 한 칸 차이 3 / MBTI 같은 자리 글자 1개당 1점 |
| 나이 | 10 | 차이 0~2세 10, 3~5세 6, 6세 이상 3 |
| 거주지 | 10 | 같은 구 10, 같은 시 6, 다르면 2 |
| 외모스타일 | 5 | 선호 키워드와 상대 외모스타일이 하나라도 겹치면 5 (선호가 빈칸이면 충족) |
| 경제·학력 | 5 | 희망연봉_최소구간 이상(빈칸이면 충족) 3 + 학력 차이 한 단계 이내 2 |

선호에 기대는 항목(나이·외모스타일·경제)은 양방향으로 계산해 평균합니다(그래서 2.5점 같은 값이 나옵니다).
동점이면 가치관 → 생활습관 → 번호 순입니다. 외모·연봉 배점이 작은 이유는, 배우자 조건 1순위는 성격이고
오래가는 관계는 가치관·생활습관이 좌우하기 때문입니다.

## v2 기믹: 이번 시즌

1~4단계는 v1 그대로이고, 그 뒤에 예능식 시즌이 붙습니다. 작업 지시문 전체는
[docs/v2-기믹-프롬프트.md](docs/v2-기믹-프롬프트.md)에 있습니다.

| 단계 | 기믹 | 하는 일 |
|---|---|---|
| 5 | 의외의 궁합 | 임베딩 후보 10명에 못 들었지만 규칙 점수가 높은 사람을 따로 보여 줌 |
| 5 | 각자 다르게 보기 | **시즌 호감도** = 궁합(내 `중요항목` 2.5배 가중) + 첫인상(±20, 방향마다 따로). A→B와 B→A가 달라짐 |
| 5 | 엇갈린 화살표 | 호감도 1위 기준 쌍방·짝사랑·인기 집중·삼각관계 |
| 5 | 안정 매칭 | 게일-섀플리로 "서로 지금 짝보다 더 원하는 쌍이 없는" 조합. **남 제안·여 제안을 둘 다 돌려** 짝이 달라지는 사람을 보여 줌 |
| 5 | 쌍방 확인 | 안정 매칭 짝 + 서로 상위 2위 + 양쪽 호감도 85 이상 → 72시간 여행 |
| 6 | 72시간 여행 | 이벤트 10개 중 6개(비 오는 날, 술자리, 길 잃기 …)가 성향 차이를 시험. 시드 = 시즌 + 정렬한 두 번호 |
| 7 | 커플·지원금 | 양쪽 최종 호감도 85 이상이면 커플. 현금 대신 **데이트 바우처**, 1·3·6개월 유지 시 분할 지급. 순위 계산에는 쓰지 않음 |

기본 설정으로 이번 시즌(2026-가을)은 **70명 → 매칭 29쌍 → 여행 10쌍 → 커플 7쌍**입니다.
쌍방이 쉽게 되지 않도록 조절했고(처음 값으로는 21쌍이 커플), 조절 기록은 프롬프트 문서에 있습니다.

## 숫자 바꾸기

`match.py` **맨 위 설정 블록** 한 곳만 고치면 됩니다.

- `K = 10`: 임베딩에서 넘길 후보 수
- `POINTS = {...}`: 위 점수표의 모든 배점 (항목별 만점 `MAX`는 자동 계산)
- `AGE_BANDS = (2, 5)`: 나이 점수 구간 경계 (≤2세, ≤5세, 그 이상)
- `SCALES = {...}`: "한 칸 차이"를 셀 때 쓰는 값의 순서
- v2 기믹 설정: `SEASON`(바꾸면 첫인상·여행이 새로 섞임), `WEIGHT_IMPORTANT`, `FIRST_IMPRESSION`, `PROPOSER`,
  `MUTUAL_TOP`·`MUTUAL_MIN`(여행 자격), `TRIP_EFFECT`·`TRIP_LUCK`(여행 난이도), `COUPLE_MIN`, `SUBSIDY_TIERS`·`SUBSIDY_SCHEDULE`

## 자체 점검

실행할 때마다 `self_check()`가 assert로 확인하고, 하나라도 어기면 멈춥니다.

1. 나 자신과 같은 성별은 추천되지 않는다
2. 흡연 불가 조건이 작동한다
3. 통과자 0명일 때 안내가 나온다
4. 같은 입력이면 순위가 항상 똑같다

5. 중요항목이 없으면 호감도의 궁합 부분 = 규칙 점수, 첫인상은 범위 안이고 늘 같은 값
6. 남 제안·여 제안 안정 매칭 모두 '서로 더 원하는 쌍'이 없고, 짝은 거르기를 통과한 반대 성별
7. 72시간 여행은 누가 조회해도 같은 결과, 지원금 분할 합계 = 총액

2·3번은 가상 프로필을 만들어 확인하므로 CSV를 고쳐도 깨지지 않습니다.
화면으로 0명 안내를 보려면 일부러 조건을 까다롭게 넣은 `python match.py M35`를 실행하세요.

`python match.py check`는 여기에 더해 **시각화에 쓴 M06 × W22의 숫자**(프로필 원본 해시, 통과 인원, 1위,
49점, 거르기 결과, 유사도 0.908)가 그대로인지 확인합니다. 그래서 M06·W22는 `중요항목`을 비워 두었습니다.
